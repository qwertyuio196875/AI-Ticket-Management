# User 仅限内部员工

外部客户**不登录系统**。`sys_user` 只承载企业内部员工（运维、客服、管理员等）。外部客户信息以轻量档案形式存在，作为工单 `creator_id` 的关联数据，由内部员工代客录入。

## 为什么

外部客户一旦能登录，会引入独立的注册/找回密码/手机验证/开放注册安全防护等完整链路，并冲击 RBAC 的 actor 模型——目前的 `sys_user/role/menu/role_menu/user_role` 完全是内部员工视角设计的。当前阶段目标是企业级后台能力，外部门户是后续独立项目。

## 影响

- 未来若加客户门户，需新增 `customer_user` 表，独立 RBAC 链路，不复用 `sys_*`。
- 工单创建 API 仅对内部员工开放（需要 `@PreAuthorize("hasAuthority('ticket:create')")`）。
- "报障"动作由客服/运维在后台发起；客户档案字段（电话、所属公司）随工单一并录入。
